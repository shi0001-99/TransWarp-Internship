## 第一部分：项目总览

### 1.1 这个项目是什么

**TransAlpha** 是一个**量化投资决策支持系统**（注意不是自动交易系统）。它做的事用一句话概括：

> 用程序自动筛选股票、分析趋势、计算仓位、监控预警，但在关键节点必须由人类拍板。

打个比方：它就像一个**智能投研助理**——帮你收集数据、做计算、给建议，但最后买不买、买多少，还是你说算。

### 1.2 它能做什么

| 能力 | 说明 |
|------|------|
| 🔄 选股筛选 | 从全A股或热门股池中，按基本面+技术面+资金面打分，选出 Top10 |
| 📈 趋势分析 | 对通过的股票做技术指标分析（13种指标+20+种形态）+ 蒙特卡洛预测 |
| 💰 仓位计算 | 用半凯利公式给出每只股票建议买多少股、投多少钱 |
| 🚨 实时监控 | 对持仓股票做 7 大规则预警（止损/止盈/异动/均线/RSI/缺口/回撤） |
| 👨‍💼 人机协作 | 在抽查、确认、审查 3 个关键节点暂停，等人类决策 |

### 1.3 它不能做什么

| 不能做的事 | 原因 |
|-----------|------|
| ❌ 自动下单交易 | 没有对接券商交易API |
| ❌ 保证盈利 | 量化模型有误差，市场有不确定性 |
| ❌ 替代人类决策 | 设计哲学就是"AI辅助，人类主导" |
| ❌ 实时高频交易 | 数据源是新浪/东财免费接口，有延迟 |

### 1.4 核心设计哲学：HABP协议

项目遵循 **HABP（Human-AI Boundary Protocol）人机边界协议**：

- **刚性边界**（机器主导，人类抽查）：如财务指标计算、风控规则校验
- **柔性边界**（人类主导，AI建议）：如策略适用性评分、尾部情景构建

流水线在 3 个柔性边界节点暂停，等待人类决策。这是整个项目的灵魂。

## 第二部分：先懂概念——量化投资入门

在拆解代码前，先用 5 分钟理解几个核心概念。

### 2.1 什么是量化投资

**传统投资**：老王看新闻→听消息→凭经验买股票→凭感觉卖
**量化投资**：程序收集数据→按公式打分→按规则买→按规则卖

量化投资的核心是**把投资决策写成规则，让程序执行**，避免情绪干扰。

### 2.2 量化投资的基本流程

```
数据采集 → 选股筛选 → 信号生成 → 仓位计算 → 风控校验 → 实盘交易 → 监控预警
   ↑                                                                    |
   └──────────────────── 反馈优化 ←────────────────────────────────────┘
```

本项目实现了前 6 个环节（除实盘交易）。

### 2.3 关键术语速查表

| 术语 | 解释 | 类比 |
|------|------|------|
| **ROE** | 净资产收益率，衡量公司赚钱效率 | 每投入100元本金能赚多少 |
| **PE** | 市盈率，股价/每股收益 | 多少年能回本 |
| **PB** | 市净率，股价/每股净资产 | 资产溢价多少倍 |
| **MA5/10/20** | 5/10/20日移动平均线 | 近期平均成本 |
| **RSI** | 相对强弱指标（0-100） | 超买(>70)还是超卖(<30) |
| **MACD** | 指数平滑异同移动平均线 | 趋势的动量 |
| **K线** | 记录一日开盘/收盘/最高/最低 | 股价心电图 |
| **凯利公式** | 最优仓位比例公式 | 赌注该下多少 |
| **止损/止盈** | 亏/赚到多少就卖 | 风险控制线 |

### 2.4 本项目在量化投资中的位置

本项目属于**多因子选股+趋势跟踪+凯利仓位**的组合策略：

- **选股**用多因子模型（基本面+技术面+资金面打分）
- **择时**用技术指标（MA/MACD/RSI/形态）
- **仓位**用半凯利公式（安全边际）
- **风控**用七大预警规则（止损止盈+异动监控）

### 5.3 状态管理机制

流水线通过 `output/pipeline_state.json` 管理状态。核心代码在 [pipeline.py](file:///d:/18976/星环科技实习/TransAlpha工作流/src/pipeline.py#L46-L59)：

```python
def _read_state() -> dict[str, Any]:
    """读取流水线状态"""
    if STATE_FILE.exists():
        try:
            return json.loads(STATE_FILE.read_text(encoding="utf-8"))
        except (json.JSONDecodeError, UnicodeDecodeError):
            pass
    return {}

def _write_state(state: dict[str, Any]) -> None:
    """写入流水线状态"""
    STATE_FILE.write_text(
        json.dumps(state, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )
```

这种设计的优点：
- **断点续跑**：程序中断后，下次启动能从上次的位置继续
- **可观察性**：任何时候都能查看 `pipeline_state.json` 了解进度
- **可回滚**：手动修改状态文件可以重跑某个阶段

#### 6.1.2 pipeline.py — 流水线编排

[pipeline.py](file:///d:/18976/星环科技实习/TransAlpha工作流/src/pipeline.py) 是核心调度文件，约 580 行。它定义了 7 个阶段函数和编排逻辑。

**关键架构**：

```python
# 共享数据中心（内存缓存）
class SharedDataCache:
    def __init__(self):
        self._cache = {}
    def set(self, key, value): self._cache[key] = value
    def get(self, key, default=None): return self._cache.get(key, default)

_shared = SharedDataCache()

# 阶段映射表
STAGE_MAP = {
    1: ("选股筛选", run_screening_stage),
    2: ("人工抽查", run_manual_review),
    3: ("趋势分析", run_analysis_stage),
    4: ("人工确认", run_manual_confirmation),
    5: ("凯利仓位", run_kelly_stage),
    6: ("持仓审查", run_position_review),
    7: ("实时监控", run_monitor_stage),
}

# 主编排函数
def run_pipeline(start_stage=1, monitor_duration=60):
    for stage_num in range(start_stage, 8):
        name, func = STAGE_MAP[stage_num]
        try:
            if stage_num == 7:
                func(duration=monitor_duration)
            else:
                func()
        except Exception as e:
            # 记录错误状态并退出
            state["pipeline_status"] = f"error_at_stage_{stage_num}"
            return
```

**阶段②人工抽查的实现**（CLI交互）：


#### 6.3.3 TechnicalIndicators — 12种技术指标

[calc_all](file:///d:/18976/星环科技实习/TransAlpha工作流/src/trend/stock_analysis.py#L249-L330) 方法一次性计算所有指标：

```python
@staticmethod
def calc_all(df):
    # 1. 均线 MA5/10/20/60
    df['MA5']  = close.rolling(5).mean()
    df['MA10'] = close.rolling(10).mean()
    
    # 2. MACD (DIF + DEA + MACD柱)
    ema12 = close.ewm(span=12).mean()
    ema26 = close.ewm(span=26).mean()
    df['DIF']  = ema12 - ema26
    df['DEA']  = df['DIF'].ewm(span=9).mean()
    df['MACD'] = (df['DIF'] - df['DEA']) * 2
    
    # 3. RSI(14) - 简单平均版（非Wilder平滑）
    delta = close.diff()
    gain = delta.where(delta > 0, 0).rolling(14).mean()
    loss = (-delta.where(delta < 0, 0)).rolling(14).mean()
    rs = gain / loss.replace(0, np.nan)
    df['RSI'] = 100 - (100 / (1 + rs))
    
    # 4. KDJ
    rsv = (close - low.rolling(9).min()) / (high.rolling(9).max() - low.rolling(9).min()) * 100
    df['K'] = rsv.ewm(com=2).mean()
    df['D'] = df['K'].ewm(com=2).mean()
    df['J'] = 3 * df['K'] - 2 * df['D']
    
    # 5. 布林带 BOLL
    df['BOLL_MID'] = df['MA20']
    df['BOLL_UP']  = df['MA20'] + 2 * close.rolling(20).std()
    df['BOLL_DN']  = df['MA20'] - 2 * close.rolling(20).std()
    
    # 6-12. ATR/CCI/WR/DMI/OBV/BIAS/VOL_RATIO (略)
    return df
```

#### 6.3.5 StockPredictor — 蒙特卡洛预测

```python
def predict(df, days_ahead=5):
    # 1. 计算三个信号因子
    trend_score = 0.3 if price > ma5 > ma20 else -0.3  # 趋势信号
    rsi_signal  = 0.2 if rsi < 30 else (-0.2 if rsi > 70 else 0)  # RSI信号
    macd_signal = 0.15 if dif > dea else -0.15  # MACD信号
    
    # 2. 综合预期收益（clip到±5%）
    expected_return = (trend_score + rsi_signal + macd_signal) * 0.15
    expected_return = max(-0.05, min(0.05, expected_return))
    
    # 3. 蒙特卡洛模拟2000次
    np.random.seed(42)  # 固定种子，结果可复现
    returns_sim = np.random.normal(expected_return / days_ahead, daily_vol,
                                   (2000, days_ahead))
    
    # 4. 生成价格路径
    price_paths = np.zeros((2000, days_ahead + 1))
    price_paths[:, 0] = current_price
    for t in range(days_ahead):
        price_paths[:, t+1] = price_paths[:, t] * (1 + returns_sim[:, t])
    
    # 5. 统计输出
    final_prices = price_paths[:, -1]
    return {
        "predicted_price": np.mean(final_prices),
        "up_probability": np.mean(final_prices > current_price),
        "upper": np.percentile(final_prices, 97.5),  # 95%置信上界
        "lower": np.percentile(final_prices, 2.5),   # 95%置信下界
    }
```

#### 6.4.4 凯利公式详解

[KellyCalculator](file:///d:/18976/星环科技实习/TransAlpha工作流/src/kelly/stock_kelly_analyzer.py#L2099-L2167) 实现了完整的凯利仓位计算：

**Step 1: 评分→胜率映射**（线性映射）

```python
@staticmethod
def score_to_win_probability(score):
    """评分0→胜率35%，评分10→胜率75%"""
    clamped = max(0.0, min(10.0, score))
    return 0.35 + (clamped / 10.0) * (0.75 - 0.35)
    # 即 win_prob = 0.35 + score * 0.04
```

| 评分 | 胜率 |
|------|------|
| 0 | 35% |
| 5 | 55% |
| 10 | 75% |

**Step 2: 凯利公式计算最优仓位**

```python
@staticmethod
def kelly_fraction(win_prob, avg_win_pct=0.15, avg_loss_pct=0.08):
    w = win_prob                       # 胜率
    l = 1.0 - w                        # 败率
    b = avg_win_pct / avg_loss_pct     # 盈亏比 = 0.15/0.08 ≈ 1.875
    f = (b * w - l) / b                # 凯利公式 f* = (bp - q) / b
    return max(0.0, f)                 # 不允许负仓位
```

**凯利公式原理**：
- `b` = 盈亏比（每次赚的/每次亏的）= 1.875
- `p` = 胜率
- `q` = 败率 = 1-p
- `f*` = 最优仓位比例 = (bp - q) / b

举例：胜率60%，盈亏比1.875
- f* = (1.875 × 0.6 - 0.4) / 1.875 = (1.125 - 0.4) / 1.875 = 0.387 = 38.7%

**Step 3: 半凯利缩放 + 单票上限**

```python
@staticmethod
def calculate_position(score, total_capital=1000000, current_price=0, kelly_scaling=0.5):
    # 1. 评分转胜率
    win_prob = score_to_win_probability(score)
    
    # 2. 凯利比例
    kelly_f = kelly_fraction(win_prob)
    
    # 3. 半凯利缩放（H6硬约束：kelly_scaling=0.5）
    suggested_fraction = kelly_f * kelly_scaling
    
    # 4. 单票25%上限（H9硬约束）
    suggested_fraction = min(suggested_fraction, 0.25)
    
    # 5. 计算金额
    suggested_amount = total_capital * suggested_fraction
    
    # 6. 计算股数（A股100股一手，向下取整）
    suggested_shares = int(suggested_amount / current_price / 100) * 100
    
    return {
        "win_probability": win_prob,
        "kelly_fraction": kelly_f,              # 原始凯利比例
        "suggested_fraction": suggested_fraction, # 最终建议仓位
        "suggested_amount": suggested_amount,
        "suggested_shares": suggested_shares,
    }
```

**为什么用半凯利**（H6硬约束）：

> 全凯利（f*）在数学上是最优的，但波动太大——可能连续亏损导致心理崩溃。半凯利（f*/2）牺牲20%的收益，换取50%的波动降低，提供安全边际。

```python
    tmp_path = path.with_suffix(path.suffix + '.tmp')  # 临时文件
```

### 7.4 凯利公式原理

**问题**：给定胜率和盈亏比，应该投入多少比例的资金？

**凯利公式**：

```
f* = (b·p - q) / b

其中：
f* = 最优仓位比例
p  = 胜率
q  = 败率 = 1 - p
b  = 盈亏比 = 平均盈利 / 平均亏损
```

**推导直觉**：
- 如果每次赚的比亏的多（b>1），即使胜率50%也能下注
- 如果胜率很低（p→0），仓位应该趋近于0
- 如果胜率很高（p→1），仓位应该趋近于100%

**本项目参数**：

```python
KELLY_CONFIG = {
    "kelly_scaling": 0.5,             # 半凯利缩放
    "single_max_fraction": 0.25,      # 单票上限25%
    "portfolio_max_total_pct": 0.80,  # 组合上限80%（未实现）
    "avg_win_pct": 0.15,              # 平均盈利15%
    "avg_loss_pct": 0.08,             # 平均亏损8%
}
```

**计算链路**：

```
评分(0-10) → 胜率(35%-75%) → 凯利比例 → ×0.5半凯利 → min(·, 0.25)单票上限
```

**举例**：评分7.59（紫金矿业）
1. 胜率 = 0.35 + 7.59 × 0.04 = 65.4%
2. 凯利比例 = (1.875 × 0.654 - 0.346) / 1.875 = 46.91%
3. 半凯利 = 46.91% × 0.5 = 23.45%
4. 单票上限 = min(23.45%, 25%) = 23.45%
5. 建议金额 = 1,000,000 × 23.45% = ¥234,534

### 7.5 技术指标计算原理

#### 7.5.1 移动平均线（MA）

```python
MA5 = 最近5日收盘价之和 / 5
```

**作用**：平滑价格波动，识别趋势方向。

**多头排列**：MA5 > MA10 > MA20（短期>中期>长期，上涨趋势）
**空头排列**：MA5 < MA10 < MA20（下跌趋势）

#### 7.5.2 MACD（指数平滑异同移动平均线）

```python
DIF  = EMA(12) - EMA(26)    # 快慢线差值
DEA  = EMA(DIF, 9)          # DIF的9日EMA
MACD = (DIF - DEA) × 2      # MACD柱
```

**金叉**：DIF上穿DEA → 买入信号
**死叉**：DIF下穿DEA → 卖出信号

#### 7.5.3 RSI（相对强弱指标）

```python
涨幅均值 = 近14日上涨幅度的平均
跌幅均值 = 近14日下跌幅度的平均
RS = 涨幅均值 / 跌幅均值
RSI = 100 - 100 / (1 + RS)
```

**解读**：
- RSI > 70：超买（可能回调）
- RSI < 30：超卖（可能反弹）
- RSI = 50：中性

#### 7.5.4 KDJ（随机指标）

```python
RSV = (收盘价 - 9日最低) / (9日最高 - 9日最低) × 100
K   = EMA(RSV, 3)    # K线
D   = EMA(K, 3)      # D线
J   = 3K - 2D        # J线（敏感度最高）
```

**金叉**：K线上穿D线 → 买入
**死叉**：K线下穿D线 → 卖出

#### 7.5.5 布林带（BOLL）

```python
中轨 = MA20
上轨 = MA20 + 2 × 标准差
下轨 = MA20 - 2 × 标准差
```

**作用**：价格通道，突破上轨可能超买，突破下轨可能超卖。

### 7.6 形态识别原理

#### 7.6.1 K线形态判定

**实体比例**：`body_ratio = |收盘-开盘| / (最高-最低)`

**上下影线**：
- 下影线 = `min(收盘,开盘) - 最低`
- 上影线 = `最高 - max(收盘,开盘)`

**锤子线**（看涨）：下影线长（≥60%），上影线短（≤20%），实体小（≤35%）

**射击之星**（看跌）：上影线长（≥60%），下影线短（≤20%），实体小（≤35%）

#### 7.6.2 双顶/双底识别

**5点极值法**：

```python
# 找局部高点：当前点比左右各2个点都高
if highs[i] > highs[i-1] and highs[i] > highs[i-2] \
   and highs[i] > highs[i+1] and highs[i] > highs[i+2]:
    local_highs.append((i, highs[i]))

# 双顶判定：两个高点差值<3%，间隔≥5根，跌破颈线
```

## 第八部分：HABP人机边界协议

### 8.1 协议核心思想

**HABP（Human-AI Boundary Protocol）** 定义了人机协作的边界：

- **刚性边界**：机器主导，人类抽查（如财务指标计算）
- **柔性边界**：人类主导，AI建议（如策略适用性评分）

### 8.2 任务类型边界映射

| 任务类型 | 人机边界 | 边界性质 | 判定理由 | 示例 |
|---------|---------|---------|---------|------|
| 财务指标计算 | AI主导，人类抽查 | 刚性 | 确定性程序化计算 | 市盈率计算 |
| 因子打分 | AI主导，人类抽查 | 刚性 | 基于既定公式 | 因子暴露度 |
| 策略适用性评分 | 人机协作，AI须人类确认 | 柔性 | 依赖主观研判 | 价值策略适用度 |
| 管理层质量判断 | 人类主导，AI提供参考 | 柔性 | 涉及综合判断 | 管理层是否值得信任 |
| 风控规则校验 | AI主导，禁止人工豁免 | 刚性 | 防止系统性风险 | 单一标的仓位上限 |
| 尾部情景构建 | 人类主导，AI提供案例 | 柔性 | 需要创造性推演 | 黑天鹅情景设想 |

### 8.3 本系统的暂停环节映射

| 暂停环节 | 对应任务类型 | 边界性质 | 暂停目的 |
|---------|------------|---------|---------|
| 阶段② 人工抽查 | 财务指标+因子打分 | 刚性 | 抽查AI计算是否准确 |
| 阶段④ 人工确认 | 策略适用性评分 | 柔性 | 人类决定最终买入列表 |
| 阶段⑥ 人工审查 | 策略适用性+尾部情景 | 柔性 | 人类调整仓位，覆盖凯利最优解 |

### 8.4 设计哲学

**为什么需要HABP**：

1. **防止AI静默失效**：AI可能在数据异常时仍输出结果，人类抽查是最后防线
2. **保留人类判断权**：投资是艺术+科学，主观研判不可替代
3. **风控刚性约束**：单票25%、组合80%等硬约束禁止人工豁免，防止情绪化突破

## 第十部分：已知问题与改进建议

### 10.1 pipeline.py 的接口bug

**问题**：`pipeline.py` 中多处调用接口与实际实现不匹配。

| 阶段 | 错误调用 | 正确调用 |
|------|---------|---------|
| 阶段③ | `src.screener.data_fetcher.StockAnalyzer.get_stock_analysis()` | `src.trend.stock_analysis.StockAnalyzer.analyze()` |
| 阶段⑤ | `StockKellyAnalyzer.analyze_stock()` | `StockKellyAnalyzer.analyze(silent=True)` |
| 字段名 | `symbol` | `code`（screener输出） |
| 阶段⑦ | `save_watchlist()` 保存list，pipeline又写dict覆盖 | 应保持list格式 |

**影响**：直接运行 `python run.py` 会在阶段③失败。

**修复建议**：修改 `pipeline.py` 的 import 和方法调用。

### 10.2 资金面评分未实现

**问题**：`screener.py` 的 `capital_score` 硬编码为20分满分。

**影响**：所有股票资金面都得满分，实际区分度只有80分（基本面40+技术面40）。

**修复建议**：接入北向资金、主力资金流向数据。

### 10.3 ROE趋势检查是占位实现

**问题**：`_check_roe_trend` 永远返回 `"stable"` 或 `"unknown"`，不会返回 `"declining"`。

**影响**："ROE连续3年下滑"否决条件永不触发。

**修复建议**：实现真正的多年ROE趋势分析。

### 10.4 尾盘涨幅实现与注释不符

**问题**：`calculate_tail_pct` 注释说"尾盘1小时涨幅"，实际计算的是日涨幅 `(现价-昨收)/昨收`。

**影响**：技术面评分的"尾盘拉升"项实际是"日涨幅"评分。

**修复建议**：要么修正注释，要么实现真正的尾盘涨幅（需要分钟线数据）。

### 10.5 动态止盈的elif逻辑bug

**问题**：

```python
if drawdown >= 5:
    alert("回撤5%")
elif drawdown >= 10:  # 永远不会触发
    alert("回撤10%")
```

**影响**：回撤≥10%时只会提示"回撤5%"，不会提示"建议清仓"。

**修复建议**：把两个条件反过来：

```python
if drawdown >= 10:
    alert("回撤10%，建议清仓")
elif drawdown >= 5:
    alert("回撤5%，建议减仓")
```

### 10.6 组合80%上限未实现

**问题**：`KELLY_CONFIG["portfolio_max_total_pct"] = 0.80` 仅定义未使用。

**影响**：多只股票仓位相加可能超过80%。

**修复建议**：在 `StockKellyAnalyzer` 增加组合级仓位汇总校验。

### 10.7 黑名单不中断流程

**问题**：`check_blacklist` 返回 `is_blacklisted=True` 后，`analyze` 方法仍继续评分和凯利计算。

**影响**：黑名单形同虚设。

**修复建议**：在 `analyze` 中检测到黑名单后直接返回不买入建议。

### 10.8 估值数据缺陷

**问题**：`_get_valuation_baostock` 用 `hash(bs_code)` 生成伪PE/PB。

**影响**：PE分位检查形同虚设，黑名单的PE条件无法触发。

**修复建议**：改用akshare获取真实PE/PB分位数据。

### 10.9 蒙特卡洛用固定种子

**问题**：`np.random.seed(42)` 固定种子，导致同一只股票多次预测结果相同。

**影响**：不同股票间的预测分布有偏，可复现但不够随机。

**修复建议**：使用 `np.random.default_rng()` 无固定种子。

### 10.10 容错策略命名不准确

**问题**：文档说"指数退避"，实际是固定延迟（0.5秒/1秒）。

**修复建议**：实现真正的指数退避（1s, 2s, 4s, 8s...）。
