# 子流程：③ 信息收集

> **对应流水线环节**：③ 信息收集｜工具层
> **前置文档**：`main_auto_workflow.md`、`TransAlpha小组投资信仰手册.md`、`TransAlpha赛道景气度打分表.md`
> **后置环节**：⓪ 人工审查① → ④ 公司研究

---

## 目标

从多数据源获取 A 股全市场股票的行情数据、基本面数据、资金流数据，建立**全市场数据台账**，为公司研究和因子打分提供标准化输入。

> **设计依据**：
> - `TransAlpha小组投资信仰手册.md` 1.1 节"全行业覆盖"——重点跟踪食品饮料、高科技（半导体/AI/机器人）、矿产资源（有色/煤炭）、机械设备、医疗医药、新能源、数字经济等所有热门板块
> - `TransAlpha赛道景气度打分表.md` 1.1 节"短线三层信息源"——盘前层/盘中层/盘后层信息源规范
> - `AI量化投资流水线(1).md` ③ 信息收集——"统一信息数据源：财报、行业研报、产业新闻、上下游数据；建立信息溯源规范"

## 数据源与优先级

### 主数据源链（akshare 优先，多源容错）

| 优先级 | 数据源 | 用途 | 接口 | 备注 |
| --- | --- | --- | --- | --- |
| 主源1 | akshare - 新浪财经 | 全A股列表+行情 | `ak.stock_zh_a_spot()` | 5538只，含行情，耗时约26s |
| 主源2 | akshare - 代码名称 | 全A股代码清单 | `ak.stock_info_a_code_name()` | 5539只，仅代码+名称，10s |
| 备源 | 东方财富直连 | 实时行情、财务指标 | `data_fetcher.py` 内置3备份域名 | 当前环境不稳定 |
| 降级 | 热门龙头股池（59只） | 全部不可用时启用 | `_get_hot_stocks()` | **必须明示降级**，供⓪人工审查①检查 |

> **禁止**绕过 `data_fetcher.py` 直接调用上述 API。所有数据获取必须走容器层，确保多源备份+指数退避重试。

### 短线三层信息源（依据赛道景气度打分表）

| 层级 | 时间周期 | 核心关注点 | 信息源 | 收集方式 |
| --- | --- | --- | --- | --- |
| 盘前层 | 盘前 30 分钟 | 隔夜美股/港股表现、外围市场情绪、重要新闻与政策（MLF利率、行业突发事件）、龙虎榜动向 | 财联社电报、华尔街见闻、交易所公告 | 人工+AI辅助（待接入） |
| 盘中层 | 盘中 4 小时 | 板块资金净流入/流出、涨停/跌停家数、连板高度、龙头股封板强度、量能变化 | 东方财富 Level-2、同花顺、通达信 | `data_fetcher.py` 实时行情接口 |
| 盘后层 | 盘后 30 分钟 | 龙虎榜席位分析、北向资金流向、融资融券变化、行业研报速递 | 东方财富龙虎榜、交易所数据中心 | `fetch_batch_northbound()` + `fetch_batch_dragon_tiger()` |

> **规则**（来自赛道打分表）：短线交易只做"盘前预判 + 盘中确认"。盘前层决定关注方向，盘中层决定是否介入，盘后层为次日做准备。

## 收集的指标清单

### 1. 基本面指标（每季度更新）

> 基本面指标分两类：**质量筛查指标**用于"一票否决"（快速排除差公司），**估值评估指标**用于打分排序。

#### 1a. 质量筛查指标 —— 筛选用，少而精

| 指标 | 字段名 | 筛选用途 | 否决标准 |
| --- | --- | --- | --- |
| ROE | `roe` | 连赚钱的能力都没有？ | ROE < 3% 且连续3年下滑 → 排除 |
| 净利润增长率 | `net_profit_growth` | 生意是不是在萎缩？ | 连续2年负增长 → 排除 |
| 自由现金流 | `free_cash_flow` | 赚的是纸面利润还是真金白银？ | 连续2年为负 → 排除 |
| 资产负债率 | `debt_ratio` | 会不会被债压垮？ | 超过行业阈值（自适应）→ 排除 |

#### 1b. 估值评估指标 —— 打分组用，全面参考

| 指标 | 字段名 | 用途 |
| --- | --- | --- |
| 市盈率 | `pe` | 估值水平（PE低不一定好，需结合行业增速） |
| 市净率 | `pb` | 估值水平（银行/地产更看重PB） |
| 股息率 | `dividend_yield` | 稳健回报（高股息率适合防守型标的） |
| 净利润 | `net_profit` | 绝对盈利规模 |
| 营业收入 | `revenue` | 业务规模 |
| 扣非净利润 | `net_profit_excl_nonrecurring` | CH-4 EP 因子严格计算用 |

### 2. 技术面指标（每日更新）

| 指标 | 字段名 | 用途 |
| --- | --- | --- |
| 20日均线 | `ma20` | 趋势判断（核心） |
| 10日均线 | `ma10` | 中短期趋势判断 |
| 5日均线 | `ma5` | 短期趋势判断 |
| 5日均量 | `vol_ma5` | 量能判断 |
| 换手率 | `turnover_rate` | 市场关注度 |
| 近5日涨幅 | `pct_5d` | 短期动量 |
| 近20日涨幅 | `pct_20d` | 中期动量 |
| 前一日尾盘涨幅 | `tail_pct` | 尾盘拉升信号 |
| 流通市值 | `circ_market_cap` | 盘口筛选 |
| 成交量趋势 | `vol_trend` | 连续性放量判断 |
| 均线多头排列 | `ma_alignment` | K线形态健康度 |

### 3. 资金面指标（每日更新）

| 指标 | 字段名 | 用途 | 数据源 |
| --- | --- | --- | --- |
| 北向资金净流入 | `north_flow` | 外资动向 | `fetch_batch_northbound()` |
| 主力净流入 | `main_flow` | 主力资金动向 | 东方财富资金流接口 |
| 龙虎榜数据 | `dragon_tiger` | 游资/机构席位动向 | `fetch_batch_dragon_tiger()` |

### 4. 板块热度指标（依据赛道景气度打分表六维模型）

| 维度 | 权重 | 字段名 | 数据来源 |
| --- | --- | --- | --- |
| 资金驱动力 (Capital) | 25% | `capital_score` | 主力资金净流入排名、北向资金净买入额 |
| 连板高度 (Height) | 20% | `height_score` | 板块内涨停家数、最高连板数 |
| 技术形态 (Tech) | 20% | `tech_score` | 板块指数均线、MACD、成交量 |
| 催化强度 (Catalyst) | 15% | `catalyst_score` | 政策利好、业绩预告、事件驱动 |
| 龙头辨识度 (Leader) | 10% | `leader_score` | 板块内情绪龙头是否存在 |
| 市场认可度 (Market) | 10% | `market_score` | 涨幅排名、换手率排名、成交额排名 |

> 板块总分 ≥ 75 → 🟢 首选介入；55-74 → 🟡 观察参与；< 55 → 🔴 禁止参与。本环节只收集数据，不做决策。

## 执行步骤

```
Step 1: 检查 stock_list_cache.json 是否在 7 天有效期内
  ├─ 有效 → 跳过 Step 2，直接用缓存列表
  └─ 过期 → 进入 Step 2

Step 2: 调用 data_fetcher.get_all_a_stocks(max_count=0) 获取全 A 股列表（~5500只）
  ├─ 主源1: ak.stock_zh_a_spot() (新浪，5538只)
  ├─ 主源2: ak.stock_info_a_code_name() (5539只，仅代码名称)
  ├─ 备源: 东方财富直连 (3备份域名)
  └─ 降级: 热门龙头股池 (59只) → 必须在输出中标注 degraded=true

Step 3: 行业识别（两级分类）
  ├─ 关键词匹配 → 初步定位 industry_level1 + industry_level2
  ├─ 代码前缀辅助 (600主板/000深成指/300创业板/688科创板)
  └─ 后续接入东方财富行业API → 精准识别

Step 4: 对每只股票调用 data_fetcher.fetch_batch_quotes() 批量获取实时行情
  ├─ 主源成功 → 返回数据
  ├─ 主源失败 → 间隔 2s → 4s → 8s 重试
  └─ 重试3次仍失败 → 切换备源 → 全部失败 → 跳过该股票并记录日志

Step 5: 获取资金面增强数据（批量，限前200只）
  ├─ fetch_batch_northbound() → 北向资金数据
  └─ fetch_batch_dragon_tiger() → 龙虎榜数据

Step 6: 获取板块热度数据（依据赛道景气度打分表六维模型）
  ├─ 各板块资金净流入排名
  ├─ 涨停家数/连板高度
  └─ 板块指数技术形态

Step 7: 输出全市场数据台账 → output/info-collection/market_data.json
  ├─ 标注数据源、股票数量、缺失率
  ├─ 标注是否降级 (degraded 字段)
  └─ 传递给 ⓪ 人工审查①
```

## 注意事项

1. **行业识别必须在此阶段完成**：采用"两级分类"体系，优先关键词匹配，后续接入东方财富行业API做精准识别。识别结果同时打上 `industry_level1` 和 `industry_level2` 标签。
2. **行业自适应阈值必须配合二级分类**：仅用一级分类（如"金融"）做阈值不够精细，必须用二级分类（如"金融.股份制银行"）才能给出准确阈值。
3. **缓存文件不得篡改**：`stock_list_cache.json` 内含时间戳，过期后由系统自动刷新。
4. **降级必须透明**：任何降级行为必须在输出 JSON 中标注 `degraded: true` 和 `degrade_reason`，供⓪人工审查①检查。禁止静默降级。
5. **日志必须记录**：每次 API 切换、缓存命中/过期、降级事件都要 `print` 带时间戳的日志。
6. **数据溯源规范**（来自 `AI量化投资流水线(1).md`）：任何结论必须标注来源、数据时间。台账中每条数据记录 `data_source` 和 `fetch_time`。
7. **全行业覆盖**（来自信仰手册）：不得因数据获取困难而人为缩减行业覆盖范围。如某行业数据缺失率高，应在 `data_completeness` 中标注，由⓪人工审查①决定是否接受。
8. **禁止模拟数据**（来自信仰手册 1.4 节）：当第三方 API 不可用时，AI 必须返回空列表或硬编码备用池，严禁生成"模拟 K 线"或"伪造数据"。
9. **`market_cap` 补全链**（v3.2 实现）：`get_all_a_stocks()` 返回的列表可能 `market_cap=0`（akshare 新浪源不含市值）。`run_info_collection_stage` 会调用 `fetcher.enrich_market_cap(stocks)` 批量补全，优先级：`ak.stock_zh_a_spot_em()`（东方财富 via akshare，含"总市值"列）→ Eastmoney clist API 直连（`f20` 字段分页拉取）→ 降级保持 0（print 警告，不静默）。补全前后覆盖率写入 `quality.has_market_cap_rate`。
10. **`sector_heat_score` 为简化代理版**（v3.2 实现）：六维热度打分当前基于现有每股数据（`change_pct`/`amount`/`turnover`）按 `industry_level2` 聚合计算，**并非完整六维**。代理维度如下：
    - ✅ **资金驱动力 (25%)**：sector 总成交额 / 平均板块成交额 × 100（完整计算）
    - 🔶 **连板高度 (20%)**：仅检测当日涨停（`change_pct≥9.8%`），无连板历史（代理）
    - 🔶 **技术形态 (20%)**：用日涨幅 + 上涨家数占比代理，未算 MA/MACD（代理）
    - ⚠️ **催化强度 (15%)**：置中性 50（无新闻数据，`proxy_dimensions: ["catalyst"]` 标注）
    - 🔶 **龙头辨识度 (10%)**：用 top1-top2 涨幅差代理（代理）
    - ✅ **市场认可度 (10%)**：涨幅/换手率/成交额三项排名综合（完整计算）

    `decision` 阈值对齐赛道景气度打分表：≥75 首选介入 / 55-74 观察参与 / <55 禁止参与。完整六维需接入 K 线历史（技术形态）、资金流接口（资金驱动力）、新闻数据（催化强度），待后续增强。
