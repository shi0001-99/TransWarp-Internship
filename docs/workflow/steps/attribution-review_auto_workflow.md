## 目标

对 ⑨ 调仓执行产出的交易记录和 ⑦ 回测校验的绩效结果进行**收益归因拆解**，区分运气收益与方法论收益，生成复盘日志，并输出方法论更新建议，回流至 ① 投资信仰手册和 ② 赛道景气度打分表，形成"信仰 → 赛道 → 信息 → 研究 → 打分 → 组合 → 回测 → 风控 → 执行 → 复盘 → 信仰"的完整迭代闭环。

> **核心原则**（来自 `AI量化投资流水线(1).md`）：
> - 区分运气收益与方法论收益
> - 复盘结论更新《投资信仰手册》与打分规则
> - 形成闭环迭代，不能只记录不改进

## 二、收益归因拆解

> 来自 `AI量化投资流水线(1).md` ⑩ 归因复盘——"拆解收益来源：赛道贡献、个股 alpha、择时收益"。

### 归因公式

```
总收益 = 赛道贡献 + 个股 Alpha + 择时收益 + 随机误差

赛道贡献 = 行业平均涨幅 × 仓位权重
个股 Alpha = 个股涨幅 - 行业平均涨幅
择时收益 = 实际持仓收益 - 满仓持有收益
随机误差 = 总收益 - 赛道贡献 - 个股 Alpha - 择时收益
```

### 归因维度

| 维度 | 计算方式 | 说明 |
| --- | --- | --- |
| 赛道贡献 | Σ(行业平均涨幅 × 该行业仓位权重) | 运气收益：来自行业普涨 |
| 个股 Alpha | Σ(个股涨幅 - 行业平均涨幅) × 仓位 | 方法论收益：来自个股选择 |
| 择时收益 | 实际持仓收益 - 满仓持有收益 | 方法论收益：来自 MA20 择时 |
| 随机误差 | 总收益 - 上述三项 | 不可解释部分 |

> **区分运气与方法论**（来自 `AI量化投资流水线(1).md`）：赛道贡献是运气收益（行业普涨），个股 Alpha 和择时收益是方法论收益（选股和择时能力）。

## 三、规则遵守检查

> 对照 `TransAlpha小组投资信仰手册.md` 第 1.3 节"交易纪律"逐条检查。

| # | 检查项 | 规则 | 检查方式 |
| --- | --- | --- | --- |
| D1 | 追强不抄底 | 只做强势股、热点板块龙头 | 检查买入股票是否板块热度 ≥ 55 |
| D2 | 快进快出 | 止盈 3-5%，止损 -2% | 检查实际止盈止损是否达标 |
| D3 | 不过夜风险 | T+2 收盘前未达预期必须减仓 | 检查 T+2/T+3 持仓处理 |
| D4 | 板块优先 | 选股顺序：板块热度 → 龙头 → 技术形态 | 检查买入逻辑是否遵循顺序 |
| D5 | 信号消失即离场 | 技术信号破坏立即离场 | 检查信号破坏后的处理时效 |
| D6 | 最大持仓天数 | ≤ 3 天 | 检查是否有超 T+3 持仓 |
| D7 | 单票最大仓位 | ≤ 10% | 检查实际仓位是否超标 |
| D8 | 单行业最大仓位 | ≤ 30% | 检查行业集中度 |
| D9 | 日最大亏损 | ≤ 2% | 检查单日亏损是否超标 |
| D10 | 组合最大回撤 | ≤ 5% | 检查回撤是否触发熔断 |

## 五、闭环规则

```
复盘结论 → 更新《投资信仰手册》（TransAlpha小组投资信仰手册.md）
         → 更新赛道打分表（TransAlpha赛道景气度打分表.md）
         → 更新打分因子权重（stock-scoring_auto_workflow.md）
         → 更新风控规则（risk-check_auto_workflow.md）
         → 更新卖点规则（rebalance-execution_auto_workflow.md）
         → 下一轮选股使用新规则
```

> **闭环要求**（来自 `AI量化投资流水线(1).md`）：发现问题 → 更新规则 → 下一轮验证，不能只记录不改进。复盘结论必须回流到前置文档。

## 执行步骤

```
Step 1: 读取 ⑨ 调仓执行输出的交易记录
  └─ output/rebalance-execution/orders.json

Step 2: 读取 ⑦ 回测校验输出的绩效指标
  └─ output/backtest/metrics.json + equity_curve.csv

Step 3: 收益归因拆解
  ├─ 计算赛道贡献（行业平均涨幅 × 仓位权重）
  ├─ 计算个股 Alpha（个股涨幅 - 行业平均涨幅）
  ├─ 计算择时收益（实际持仓收益 - 满仓持有收益）
  └─ 区分运气收益 vs 方法论收益

Step 4: 规则遵守检查
  ├─ 对照信仰手册 1.3 节交易纪律逐条检查（D1-D10）
  └─ 记录违规情况和改进措施

Step 5: 板块热度校准
  ├─ 对照赛道打分表的预测得分 vs 实际表现
  └─ 输出赛道打分表校准建议

Step 6: 生成复盘日志
  ├─ 按复盘文档模板填写
  ├─ 输出方法论更新建议
  └─ 标注需更新的前置文档清单

Step 7: 输出复盘日志 → output/attribution-review/review_log.md
  └─ 闭环回流至 ① 投资信仰手册 + ② 赛道打分表（人工更新）
```

## 注意事项

1. **复盘必须闭环**（来自 `AI量化投资流水线(1).md`）：发现问题 → 更新规则 → 下一轮验证，不能只记录不改进。
2. **区分运气与方法论**（来自 `AI量化投资流水线(1).md`）：收益来自行业普涨（运气）还是个股选择（方法论），归因时要分开。
3. **硬约束 H6**（来自原 review-backtest）：所有交易必须可追溯。复盘时如果发现"无依据临时交易"，需在复盘日志中标记并反思。
4. **信仰手册更新**：复盘结论如涉及风险红线调整（如止盈止损位、T+N 天数），必须经全体成员重新评估后更新 `TransAlpha小组投资信仰手册.md`，不得 AI 单方面修改。
5. **赛道打分表校准**：复盘结论如涉及六维热度权重调整，需更新 `TransAlpha赛道景气度打分表.md` 的权重分配。
6. **T+3 强制平仓回顾**：信仰手册要求最大持仓天数 ≤ 3 天，复盘时必须检查是否有超 T+3 持仓，分析原因（信号未触发？人工干预？）。
7. **当前实现状态**：`src/attribution/review.py` 待建，当前由 `review-backtest_auto_workflow.md` 中的归因复盘模板临时承接。后续需独立模块化。
