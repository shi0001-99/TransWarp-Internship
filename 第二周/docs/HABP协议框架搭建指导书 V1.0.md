# HABP协议框架搭建指导书

**Human-AI Boundary Protocol · 人机功能边界协议**

**适用对象**：组合投资实训营各小组　**建议使用阶段**：第2周（AI基础与HABP协议实战）　**前置条件**：已完成第1周人工分析流程搭建

---

## 一、写在前面：这份指导书要解决什么问题

进入第2周，你的团队将开始把第1周搭建的人工分析流程逐步改造为人机协作流程。这时最容易出现两种失败模式：

- **一是"全部甩给AI"**：图省事，把研究、判断、决策都交给AI处理，团队逐渐丧失对分析结论的真正理解，一旦被追问"为什么这么判断"就答不上来；
- **二是"完全不信AI"**：出于谨慎，事事都要人工重做一遍，团队效率低下，AI协作流于形式，无法体现AI-Native的设计初衷。

HABP协议的作用，就是在这两种极端之间，为团队建立一套**显性的、可执行的、可追溯的**人机分工规则，避免"分工"变成一句空话或者随口一说的默契。

**核心原则只有一句话：让每一次"谁来做、谁负责"的决定，事先说清楚、事后可追溯，而不是临场随意决定。**

本指导书将带领你的团队，用7个步骤，在第2周内完整搭建起本团队的HABP协议。

---

## 二、核心概念：两层边界

在动手搭建之前，必须先理解HABP协议的两层结构，这是整份指导书的地基。

### 第一层边界：人机边界（回答"谁来做"）

对团队正在执行的每一项具体任务，回答三选一：

| 分工方式     | 含义                            |
| -------- | ----------------------------- |
| **人类主导** | AI最多提供背景信息，最终判断与结论必须由团队成员独立形成 |
| **AI主导** | AI独立完成，人类只做抽查复核，不逐项重做         |
| **人机协作** | AI先给出建议或初稿，人类必须审阅、修改、确认后才能采用  |

### 第二层边界：机器内部的刚性边界与柔性边界（回答"AI做的部分里，哪些不能变、哪些可协商"）

这一层容易被忽略，但恰恰是HABP协议区别于一般"人机分工表"的关键。凡是划归"AI主导"或"人机协作"的任务，还需要进一步追问：**这项任务的AI产出，是不是无论问哪个模型、换哪句提示词，答案都应该一样？**

| 边界性质     | 判定标准                             | 团队应对方式                              |
| -------- | -------------------------------- | ----------------------------------- |
| **刚性边界** | 任务本身是确定性的程序化计算，存在唯一正确答案，不依赖主观判断  | AI计算结果原则上直接采用，抽查是否算错，而非质疑"算法选择是否合理" |
| **柔性边界** | 任务依赖对市场、公司、情境的主观研判，不同分析者可能得出不同结论 | AI产出只能作为参考意见，团队必须经过独立核实与讨论后才能采纳     |

> **一句话区分技巧**：把同一个问题拿去问两个不同的AI大模型，如果两次答案本应完全一致（只是措辞不同），这项任务大概率是刚性边界；如果两次答案可能实质性不同（比如一个说"建议买入"一个说"建议观望"），这项任务大概率是柔性边界。

## 三、搭建步骤

### 第1步：列出任务清单

以第1周搭建的人工分析流程（对应十步投资流程）为基础，把团队日常研究工作拆解为具体、可独立执行的任务条目。不要一次性穷尽所有可能任务，先列出**当前阶段团队实际会用到**的15-25项即可，后续可持续补充。

**建议来源**：

- 十步投资流程中的每一步骤，通常可以拆出2-4项具体任务
- 第1周人工分析流程文档中已经写明的具体动作
- 每日投资决策会议中反复出现的重复性工作

参考任务清单示例（可直接作为起点使用）：

- 提取标的公司财务报表关键指标
- 计算估值倍数（市盈率、市净率等）
- 计算技术面指标（均线、量能等）
- 检索并汇总近期行业新闻
- 撰写公司基本面研究简报初稿
- 评估当前市场行情下各类策略的适用度
- 判断管理层治理质量
- 构建非共识尾部情景
- 核算组合仓位与风控指标
- 撰写每日复盘纪要初稿

### 第2步：逐项判定人机边界（第一层）

将第1步的任务清单逐条填入表A8（模板见第五节）的"任务类型"列，团队集体讨论后填写"人机边界"列。

**讨论要点**：不要单纯凭直觉打勾，每一项都要能说出理由。理由通常落在以下三类之一：

- 这项任务**有无标准答案**？有→更倾向AI主导；无→更倾向人类主导或协作
- 这项任务**出错代价大不大**？代价很大（如仓位计算错误可能导致爆仓）→即使AI能做，也应保留人类复核环节
- 这项任务**是否是团队核心竞争力所在**？如果是团队最想锻炼、最不希望被替代的能力（如商业模式判断），即使AI能做得不错，也应坚持人类主导，为的是训练而非单纯追求效率

### 第3步：对"AI主导"与"人机协作"任务，判定第二层边界

对第2步中标记为"AI主导"或"人机协作"的任务，进一步判定是刚性边界还是柔性边界，同样填入表A8"机器内部边界性质"列，并在"判定理由"列写明依据。判定时请团队至少两人独立判断后再对齐，避免单人偏见。

**常见误判提醒**：

- 不要把"AI做得很快很准"误判为刚性——速度和准确率是AI能力问题，不是边界性质问题。技术面指标计算是刚性（有唯一答案），但"当前技术面是否支持买入"是柔性（涉及研判）。
- 不要把"AI说不清楚原因"误判为柔性——如果任务本身有唯一正确答案，只是AI偶尔算错，那仍然是刚性边界，解决方式是加强抽查，而不是改判为柔性。

### 第4步：设计AI置信度标注方式

对所有"AI主导"或"人机协作"任务，要求AI（或使用AI的团队成员）在产出结果时，附带一个简短的置信度说明，格式建议统一为：

> 【置信度：高/中/低】【依据：___】

- 刚性边界任务，置信度通常应为"高"，若AI自评为"中"或"低"，应触发人工复核而非直接采纳
- 柔性边界任务，无论AI自评置信度高低，均须经过人类确认环节，置信度标注此时的作用是帮助人类判断"这次AI的建议有多大把握"，作为讨论的起点而非结论

### 第5步：设计人类验证清单

针对每一类柔性边界任务，团队应提前约定"验证时至少要检查哪几点"，避免验证环节流于走过场。例如"策略适用性评分"这一任务的验证清单可以是：

- [ ] AI给出的评分依据是否引用了具体、可核实的数据（而非泛泛而谈）
- [ ] 是否考虑了近期发生的、AI训练数据可能未覆盖的最新事件
- [ ] 团队内是否有成员持不同意见，若有是否已充分讨论

### 第6步：设计责任归属声明

每一项任务完成后，须在记录中注明最终结论的责任人（通常是审阅确认的团队成员姓名，而非"AI"）。这一步的意义不是追责，而是确保**"谁签字确认，谁就要能讲清楚这个结论"**，防止责任在人机协作中被稀释、无人能对最终结论负责的情况出现。

### 第7步：设计"三重质疑"流程（用于柔性边界任务的AI输出）

对柔性边界任务的AI输出，团队在采纳前应完成三重质疑，建议形成书面记录（哪怕只是几句话）：

1. **数据溯源**：AI这个结论用了哪些数据？这些数据是最新的吗？来源可靠吗？
2. **假设识别**：AI的结论隐含了哪些没有明说的假设？这些假设成立吗？
3. **逻辑反向推演**：如果结论是错的，最可能是哪个环节出了问题？

## 六、常见误区提醒

**误区一：把边界当成一次性任务**
边界划分不是搭建完就一劳永逸的事情。团队能力在提升，AI工具本身也在迭代，某项任务今天判定为"柔性"，几周后团队对该类任务的把握力提升了，也可以考虑收窄为更倾向AI主导（但仍需团队集体讨论决定，不要单人擅自更改）。建议每周投资决策会议中留出5-10分钟，回顾是否有边界需要调整。

**误区二："伪刚性"——为了省事把本该保留判断的任务强行归为刚性**
如果团队发现自己经常在"抽查"环节直接跳过、从不认真核实AI在某项"刚性"任务上的输出，要警惕这项任务是不是其实包含了未被识别的柔性成分，被错误地简化处理了。

**误区三："伪柔性"——把明明有标准答案的任务当成需要反复讨论的柔性任务**
如果团队发现某类任务每次讨论来讨论去，结论其实都差不多，且差异主要来自计算失误而非真实判断分歧，说明这项任务本质是刚性的，之前的"讨论"环节只是在浪费时间，应当简化流程。

**误区四：只做人机边界，跳过第二层边界**
很多团队做到"人类主导/AI主导/人机协作"这一层就停下了，误以为这就是HABP协议的全部。请务必记得，真正训练团队判断力细粒度识别能力的，是第二层的刚性/柔性划分——这一层做得越细致，团队对"AI到底哪里靠谱、哪里不靠谱"的认识就越清楚。
